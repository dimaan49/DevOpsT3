# AuctionHub — HTTP API

Базовый URL: `http://localhost:8080`

Все запросы и ответы — JSON в кодировке UTF-8.

---

## Аутентификация

Аутентификация построена на **JWT** (JSON Web Token).

### Как это работает

1. Клиент отправляет email и пароль на `POST /api/auth/login`.
2. Сервер проверяет пароль и возвращает JWT.
3. Клиент сохраняет токен (`localStorage`).
4. При каждом защищённом запросе клиент отправляет токен в заголовке:

```
Authorization: Bearer <token>
```

5. Сервер проверяет подпись токена, срок жизни и blacklist отозванных токенов.
6. Если всё верно — находит пользователя по `id` из токена и выполняет запрос.

### Структура токена

JWT состоит из трёх частей, разделённых точками:

```
header.payload.signature
```

- **header** — `{"alg":"HS256","typ":"JWT"}`.
- **payload** — `{"sub":"<user_id>","iat":<issued_at>,"exp":<expires_at>}`.
- **signature** — HMAC-SHA256 от `header.payload`, подписанный секретом `AUCTIONHUB_JWT_SECRET`.

Срок жизни токена — 30 дней. По истечении `exp` токен становится невалидным.

### Logout

JWT stateless — его нельзя «удалить» из сервера. Поэтому при logout токен добавляется в таблицу `revoked_tokens` (blacklist). При следующем запросе сервер проверяет, не отозван ли токен, и отклоняет его.

### Ошибки аутентификации

- `401 unauthorized` — токен отсутствует, невалиден, истёк или отозван.
- `403 forbidden` — токен валиден, но у пользователя нет прав на операцию.

## Формат ошибок

Все ошибки возвращаются в едином формате:

```json
{
  "error": "not_found",
  "message": "Auction 42 not found"
}
```

| Код | `error` | Когда возвращается |
|-----|---------|--------------------|
| 400 | `bad_request` | Некорректный JSON, отсутствуют обязательные поля, неверный формат |
| 401 | `unauthorized` | Нет заголовка `Authorization`, токен невалиден, истёк или отозван |
| 403 | `forbidden` | Пользователь не имеет прав на операцию |
| 404 | `not_found` | Объект не найден |
| 409 | `conflict` | Операция невозможна в текущем состоянии |
| 500 | `internal_error` | Внутренняя ошибка сервера |
| 503 | `service_unavailable` | База данных недоступна (только `/health`) |

## Healthcheck

### `GET /health`

Проверка работоспособности сервиса. Не требует аутентификации.

**Ответ 200:**

```json
{
  "service": "auctionhub",
  "status": "ok",
  "database": "ok"
}
```

**Ответ 503** (если БД недоступна):

```json
{
  "service": "auctionhub",
  "status": "degraded",
  "database": "down"
}
```

## Аутентификация (эндпоинты)

### `POST /api/auth/login`

Вход по email и паролю. Возвращает JWT и данные пользователя.

**Тело запроса:**

```json
{
  "email": "user@example.com",
  "password": "secret123"
}
```

**Ответ 200:**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "email": "user@example.com",
    "role": "seller",
    "age_confirmed": true,
    "created_at": "2026-09-20T10:00:00Z"
  }
}
```

**Ошибки:**

- `400` — нет полей `email` или `password`
- `401` — неверный email или пароль

---

### `POST /api/auth/logout`

Завершение сессии. Добавляет токен в blacklist.

**Заголовки:** `Authorization: Bearer <token>`

**Ответ 200:**

```json
{
  "status": "ok"
}
```

**Ошибки:**

- `401` — нет или невалиден заголовок `Authorization`

После logout токен больше не работает, даже если срок `exp` ещё не истёк.

---

### `GET /api/auth/me`

Возвращает текущего пользователя по токену.

**Заголовки:** `Authorization: Bearer <token>`

**Ответ 200:**

```json
{
  "id": 1,
  "email": "user@example.com",
  "role": "seller",
  "age_confirmed": true,
  "created_at": "2026-09-20T10:00:00Z"
}
```

**Ошибки:**

- `401` — токен невалиден, истёк или отозван

## Пользователи

### `POST /api/users`

Регистрация нового пользователя. Не требует аутентификации.

**Тело запроса:**

```json
{
  "email": "user@example.com",
  "password": "secret123",
  "role": "seller",
  "age_confirmed": true
}
```

**Поля:**

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `email` | string | да | Email, уникальный в системе |
| `password` | string | да | Минимум 6 символов |
| `role` | string | да | `seller`, `bidder` или `moderator` |
| `age_confirmed` | boolean | да | Должно быть `true` |

**Ответ 201:**

```json
{
  "id": 1,
  "email": "user@example.com",
  "role": "seller"
}
```

**Ошибки:**

- `400` — отсутствуют поля, неверный формат email, короткий пароль, неверная роль, не подтверждён возраст
- `409` — email уже зарегистрирован

---

### `GET /api/users/{id}`

Получить пользователя по id. Не требует аутентификации.

**Ответ 200:** объект пользователя без `password_hash`.

**Ошибки:**

- `404` — пользователь не найден

## Аукционы

### `POST /api/auctions`

Создать аукцион.

**Заголовки:** `Authorization: Bearer <token>`. Только для роли `seller`.

**Тело запроса:**

```json
{
  "title": "Антикварные часы",
  "description": "Часы XIX века",
  "step": 100,
  "start_price": 1000
}
```

**Ответ 201:** объект аукциона.

**Ошибки:**

- `400` — невалидные поля
- `401` — нет или невалиден токен
- `403` — пользователь не `seller`

---

### `GET /api/auctions`

Список всех аукционов. Не требует аутентификации.

**Ответ 200:**

```json
{
  "items": [
    {
      "id": 1,
      "seller_id": 1,
      "title": "Антикварные часы",
      "description": "Часы XIX века",
      "step": 100,
      "start_price": 1000,
      "status": "active",
      "created_at": "2026-09-20T10:00:00Z"
    }
  ],
  "count": 1
}
```

---

### `GET /api/auctions/{id}`

Детали аукциона с лотами. Не требует аутентификации.

**Ответ 200:** объект аукциона с полем `lots` — массив лотов.

**Ошибки:**

- `404` — аукцион не найден

---

### `POST /api/auctions/{id}/publish`

Опубликовать аукцион. Переводит статус из `draft` в `active`.

**Заголовки:** `Authorization: Bearer <token>`. Только владелец.

**Ответ 200:** объект аукциона со `status: active`.

**Ошибки:**

- `401` — нет токена
- `403` — не владелец
- `404` — аукцион не найден
- `409` — аукцион не в статусе `draft`

---

### `POST /api/auctions/{id}/cancel`

Отменить аукцион.

**Заголовки:** `Authorization: Bearer <token>`. Только владелец.

Отмена возможна, если:

- статус `draft` или `active`;
- по лотам аукциона нет ни одной ставки.

**Ответ 200:** объект аукциона со `status: cancelled`.

**Ошибки:**

- `401` — нет токена
- `403` — не владелец
- `404` — аукцион не найден
- `409` — аукцион `finished` или `cancelled`, либо по лотам есть ставки

---

### `POST /api/auctions/{id}/lots`

Добавить лот к аукциону.

**Заголовки:** `Authorization: Bearer <token>`. Только владелец.

**Тело запроса:**

```json
{
  "title": "Часы с кукушкой",
  "description": "Рабочие",
  "start_price": 1000
}
```

**Ответ 201:** объект лота.

**Ошибки:**

- `400` — невалидные поля
- `401` — нет токена
- `403` — не владелец
- `404` — аукцион не найден

## Ставки

### `POST /api/lots/{id}/bids`

Сделать ставку.

**Заголовки:** `Authorization: Bearer <token>`.

**Правило предметной области:**

- ставка должна быть строго выше текущей максимальной;
- разница между новой ставкой и текущей должна быть кратна шагу аукциона;
- аукцион должен быть в статусе `active`.

**Тело запроса:**

```json
{
  "amount": 1200
}
```

**Ответ 201:** объект ставки.

**Ошибки:**

- `400` — нет поля `amount` или `amount <= 0`
- `401` — нет токена
- `403` — роль пользователя не позволяет делать ставки
- `404` — лот не найден
- `409` — аукцион не активен, ставка ниже текущей или не кратна шагу

---

### `GET /api/lots/{id}/bids`

История ставок по лоту. Не требует аутентификации.

**Ответ 200:**

```json
{
  "lot_id": 1,
  "current_price": 1200,
  "items": [
    {
      "id": 2,
      "lot_id": 1,
      "bidder_id": 2,
      "amount": 1200,
      "created_at": "2026-09-20T10:05:00Z"
    }
  ],
  "count": 1
}
```

**Ошибки:**

- `404` — лот не найден

## Статусы аукциона

| Статус | Описание |
|--------|----------|
| `draft` | Черновик, ещё не опубликован |
| `active` | Активен, принимает ставки |
| `finished` | Завершён |
| `cancelled` | Отменён продавцом |
